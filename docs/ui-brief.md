# 視覺方向包

給負責 UI 的人。目的是**把選擇先做完**，避免邊做邊挑。

上一場黑客松最大的瓶頸就是視覺——不是缺工具或缺資訊，是「沒有收斂成選擇題」，所以一直在改。這份就是為了不要重演。

---

## 一、定調

**這是工作工具，不是消費 App。** 冷靜、克制、資訊密度高。

- 存在感要低。待命時幾乎看不到它
- 出現時要快、要準，不要有華麗的進場
- 使用者的注意力應該在**內容**上，不在介面上

**參考對象：Raycast**。形態很接近（喚起、做完消失）。次要參考 Linear、Superhuman。

### 這個產品有兩個 surface

版面完全不同，但要看起來是同一個產品。

| Surface | 位置 | 空間 | 負責 |
|---|---|---|---|
| **浮層卡片** | 螢幕中上方，浮在別的 App 之上，寬約螢幕 90% | 充裕，可放三到四行回覆加輔助資訊 | 讀懂對話、產生回覆 |
| **鍵盤建議條** | 緊貼鍵盤上緣，橫跨螢幕寬 | **極窄**。收合約 56dp，只放得下一行提示加一個動作；展開約 160dp | 攔截使用者自己打的字 |

⚠️ 56dp 是我們的設計選擇不是平台限制（Android 唯一相關規格是最小觸控目標 48dp），視覺上需要可以改。

建議條的出現方式要**推開**內容而不是蓋住——它是鍵盤的一部分，不是浮在鍵盤上的東西。

### 兩個 surface 怎麼看起來像同一個產品

這題不解，會做出兩個看起來無關的東西。調研結論（完整版見 [refs-multi-surface.md](refs-multi-surface.md)）：

**在 56dp 裡只有五樣東西承載得了識別**，其中三樣完全免費：

1. **前緣 3dp 狀態色帶** — 兩個 surface 同寬、同位置、同色彩映射（顏色＝氣氛等級）。這是唯一同時滿足「同形狀語彙、同位置、有功能理由、幾乎不佔空間」的識別載體。**如果只能留一樣，留這個。**
2. 20dp 去容器的單色自製 glyph
3. 同一組間距數字（前緣內距 16dp／符號 20dp／符號到文字 12dp）— 免費
4. 同一組動效參數（150–250ms、ease-out、從所依附的邊長出來）— **動效不佔像素，是窄空間裡唯一沒有預算限制的識別維度**
5. 「一次只出現一個彩色」的克制，其餘走灰階 — 免費

**明確不要放**：字標、有容器的 logo、漸層，以及 ✨——那個符號識別的是「AI」不是我們的產品，等於放棄那個位置。

Apple 在比我們更小的空間（Dynamic Island compact 只有 52pt 寬）得到同一個結論：**顏色是識別，logo 不是。**

## 二、設計語言的底從哪裡來

**不要用 AI 生成的設計系統當底。** 那些沒有經過真實使用驗證，等於把一個沒被檢驗過的美學判斷變成全隊的前提。

底要從**真的出貨過的產品**拆。三種做法：

| 做法 | 工具 | 說明 |
|---|---|---|
| 看現成拆解 | [Refero Styles](https://styles.refero.design) | Linear、ChatGPT、Resend 等品牌的 `DESIGN.md` 已經拆好了，直接參考結構 |
| 自己拆一個 | `npx skills add nutlope/hallmark` → `hallmark study <網址或截圖>` | 拆解任一網站的視覺 DNA，輸出 design.md |
| 抓精確數值 | `npx dembrandt` | 開真實瀏覽器讀網站算出的樣式，吐出精確色碼／字級／間距 ⚠️ 官方明文禁止用來複刻第三方品牌識別，只能參考數值不能整套照抄 |

## 三、工具清單

### AI 補審美工作流（推薦照這條跑一遍）

從「找結構 → 找視覺互動 → 定主題 → 固化設計語言 → 給 Agent 加審美約束 → 做動效」：

| 階段 | 工具 |
|---|---|
| 找版面結構 | 21st.dev、HeroUI、Watermelon |
| 找視覺與互動靈感 | ThreeUI、beUI、Fluid Functionalism |
| 定主題（顏色圓角字級） | tweakcn |
| 固化成設計語言 | getdesign.md |
| 給 AI 加審美約束 | Taste Skill |
| 動效 | GSAP |

各工具的付費與帳號限制未逐一查證，用之前自己確認一下。

## 四、AI 味檢查清單

交付前自己掃一遍，中了就改：

- ❌ 紫藍漸層
- ❌ 玻璃擬態（frosted glass）
- ❌ 無意義的大圓角
- ❌ 用 emoji 當 icon
- ❌ 彈跳動效（bounce）

這五項是最常見的「一看就知道是 AI 生的」特徵。

## 五、介面模式摘錄

Zeno 過去對標 NotebookLM、Linear Triage、Guru、Dify 整理出的可抄模式，這裡列其中幾條（完整清單在他的筆記裡）：

- **來源固定左欄** — 資料來源常駐，不藏在選單裡
- **單一加入口 ＋ modal** — 新增只有一個入口，不要散在各處
- **停用可逆** — 任何開關都能關回去，不做不可逆的操作
- **單鍵審核動詞** — 按鈕直接寫動作（「送出」「退回」），不寫「確認」
- **二元驗證狀態** — 狀態只有兩種，不做三態四態

## 六、今晚要交的東西

**不是五個畫面。** 先出**三個設計語言方向並排**，讓 Zeno 挑一個。

理由：視覺的瓶頸是選擇不是產出。方向沒定就開始畫，會一直改。

三個方向各給：

- 一張主畫面（就用 demo 腳本裡的**畫面 2：讀空氣＋回覆生成**，那是最重要的一格）
- 配色、字級、圓角、間距的具體數值
- 一句話說明這個方向的個性

**做成一個 HTML 三欄並排**，可以直接開來看。純 HTML + CSS，不用框架。

## 七、方向定了之後才畫的五個畫面

詳細狀態見 [demo-script.md](demo-script.md)。

| # | Surface | 畫面 | 狀態 |
|---|---|---|---|
| 1 | 浮層 | 懸浮球待命 | 收起／hover |
| 2 | **浮層** | **讀空氣＋回覆生成** ⭐ | 安全牌已出現＋風險標記／文字生成中／完整回覆＋來源標註／對比展開 |
| 3 | **鍵盤** | **防自爆建議條** ⭐ | 待命（高度 0）／觸發（長出 56dp）／展開（160dp）／採用後收回 |
| 4 | — | 跨 App | 動畫或預錄 |
| 5 | — | 知識庫設定 | 靜態一張 |

**火力集中在 2 和 3。** 其他三格夠用就好。

## 八、技術限制（會影響你怎麼寫）

- **純 HTML + CSS + JS，不用框架。** 這五個畫面不需要框架
- 這些 HTML **會跑在 Android App 的 WebView 裡**，也就是說你寫的就是產品 UI 本體，不是拋棄式的稿子。不會有人拿去重刻
- 因為在手機上，**版面要照手機寬度設計**（浮層寬度大約螢幕寬 90%）
- 動態是這個 demo 的價值所在——文字要看起來像在「長出來」，卡片要「滑進來」。狀態轉換比靜態版面重要
