# Claude Design 派工單

五段 prompt，照順序貼進 Claude Design。每段跑完再貼下一段。

**專案代號**：幕僚（Aide）— 暫定，隨時可改

---

## 用哪幾段、不用哪幾段

| 階段 | 用不用 | 為什麼 |
|---|---|---|
| 概念對齊 | ✅ | 但要講清楚我們是**浮層**不是全螢幕 App |
| 靈感餵食 | ✅ **最關鍵** | 沒有參考截圖，收斂速度差十倍 |
| 設計系統 | ✅ | 導出的檔案 Brian 和簡報都要用 |
| 吉祥物 / 3D 元件 | ❌ | 工作工具放吉祥物會直接製造 AI 味 |
| Supabase 串接 | ❌ | 後端是自己寫的 API |

互動式 HTML 動畫這項留著，但用在 demo 的「跨 App」那一幕，不用在產品介面。

## 第 1 段 · 概念對齊

```
我正在開發一個 Android 上的工作訊息回覆助手，代號「幕僚」。

【形態｜這點最重要，請仔細讀】
它不是一個全螢幕 App。它有「兩個介面」，長在螢幕的不同位置，共用同一套視覺語言但版面完全不同：

**介面一：浮層卡片**
使用者在 LINE、Lark、Gmail 裡收到訊息，點一下角落的懸浮球，一張卡片浮出來，顯示 AI 讀懂這段對話後產生的回覆。處理完就消失。
- 位置：螢幕中上方，浮在別的 App 內容之上
- 寬度約螢幕寬 90%，高度依內容變動
- 空間充裕，可以顯示三到四行回覆文字加上輔助資訊

**介面二：鍵盤上方的建議條**
這是一個自訂輸入法（IME）。當使用者不採用浮層的建議、自己動手打字時，鍵盤正上方會出現一條建議條，提醒他這句話有風險，並給潤飾版本。
- 位置：緊貼在鍵盤上緣，橫跨整個螢幕寬度
- 高度受限，大約 56dp，收合狀態只能放一行提示加一個動作
- 要能向上展開顯示完整的建議句子，展開後高度約 160dp
- 出現方式是推開內容而不是蓋住——它是鍵盤的一部分

請把這兩個介面都設計出來。它們要看起來是同一個產品，而在 56dp 的窄條裡幾乎沒有空間放品牌元素，所以請優先用這幾種免費的識別手段：兩個介面共用同一組間距數字、同一組動效參數、同一套「顏色代表狀態」的映射，以及在前緣放一條同寬同位置的細色帶。不要在窄條裡放字標、有容器的 logo、漸層或 ✨ 這類符號。

【核心功能】
1. 讀懂當前螢幕上的對話
2. 判斷氣氛（一般 / 高壓 / 敏感），高壓時強制切換成「安撫＋給承諾」的回覆策略
3. 查使用者自己的知識庫（報價、交期、案子進度、這個對象的偏好），產生回覆
4. 使用者自己動手打字時，偵測防禦、推卸、火氣，跳出潤飾建議

【使用者】
業務、BD、客戶經理。每天要回大量工作訊息，回得慢會影響成交。他們的痛點是「懶得打字」加上「怕回錯話」。

【調性】
冷靜、克制、專業、不打擾。這是工作工具不是消費 App。存在感要低，使用者的注意力應該在內容上不在介面上。形態參考 Raycast（浮層、喚起、做完就消失）。

【明確禁止】
不要紫藍漸層、不要玻璃擬態、不要無意義的大圓角、不要用 emoji 當 icon、不要彈跳動效。

【技術限制】
純 HTML + CSS + JS，不用框架。這些檔案會直接跑在 Android App 的 WebView 裡，所以它就是產品 UI 本體。

請先引導我完成基礎設定，再生成初版。
```

## 第 2 段 · 餵靈感

初版一定有套版感，這正常。這一段才是決定成敗的地方。

### 去哪找參考

| 找什麼 | 去哪 |
|---|---|
| 浮層／喚起式介面的質感 | Raycast 官網截圖、Arc Browser 浮層、Superhuman command bar |
| 手機浮層與 bottom sheet | Mobbin 搜 `overlay`、`bottom sheet`、`floating` |
| 資訊密度高但不擁擠 | Linear、Height、Notion 側欄 |

**不要去 Awwwards、Godly、Landbook。** 那些是行銷網頁的視覺，跟工作工具的調性反向。

### Prompt（搭配截圖一起上傳）

```
這幾張是我心中的參考。請分析它們的共通點：版面留白、資訊密度、對比方式、圓角與陰影的使用、字級層級。

然後用同樣的視覺語言重新優化我的浮層介面。

特別注意：
- 這是浮在別的 App 上面的東西，所以邊界要清楚，但不要用重陰影或發光
- 資訊密度要高，但不能擁擠——使用者是在工作中被打斷的狀態，要能一眼掃完
- 主要內容是「一段 AI 產生的回覆文字」，它應該是畫面上唯一的主角
```

### 迭代（5–10 輪，不要期待一次到位）

一次改一件事，例如：

- 「把回覆文字的字級再拉大一級，其他資訊降一級，讓層級更清楚」
- 「風險標記現在太搶眼，改成只在浮層左緣一條細色帶」
- 「來源標籤太像按鈕了，改成不可點擊的文字標記」

## 第 3 段 · 三個方向並排 ← 今晚要交的東西

**不要直接畫五個畫面。** 先出三個方向讓人挑，方向定了再展開。

理由：視覺的瓶頸是選擇不是產出。方向沒定就開始畫，會一直改。

```
請給我三個不同的設計方向，做成一個 HTML 三欄並排，我可以直接開來比較。

每一欄要同時畫出兩個介面（因為這個產品有兩個 surface，它們要看起來是同一個產品）：

【上半：浮層卡片 · 讀空氣＋回覆生成】
- 對方傳來的訊息（一句）
- 風險等級標記（這則是「高壓局」）
- AI 產生的回覆（三到四行）
- 這句回覆引用了哪筆資料的來源標籤（例如「引用：A 案進度 · 2026-09-05」）
- 一個可展開的對比區塊：「一般 AI 會回：收到」

【下半：鍵盤上方建議條 · 防自爆】
- 一行提示：「這句帶防禦語氣，可能讓對方縮手」
- 一個「看建議」的動作
- 收合高度約 56dp，橫跨螢幕寬。請畫在一個示意的鍵盤上緣

三個方向要有明顯差異，不要只是換顏色。可以在這些軸上拉開：
- 資訊密度（極簡 vs 密集）
- 風險標記的呈現方式（色帶 / 標籤 / 背景色）
- 回覆文字的呈現（純文字 / 卡片 / 引用框）
- 兩個介面之間的視覺關聯怎麼建立（共用色帶？共用圓角語言？）

每個方向下方附：配色的具體色碼、字級、圓角、間距數值，以及一句話說明這個方向的個性。
```

## 第 4 段 · 狀態轉換 ← 我們特有的，不能省

這個 demo 的價值在動態。靜態畫面再漂亮，台上是死的。

```
方向已經定了。現在請把這個畫面的所有狀態與轉換動畫做出來，用一個 HTML 檔，我可以點按鈕在狀態之間切換來預覽。

【介面一 · 浮層卡片：讀空氣＋回覆生成】四個狀態
1. 點擊後 0.2 秒：浮層出現，已顯示一句安全開頭「收到，我確認一下進度」，同時風險標記亮起
2. 生成中：文字**接續**在安全開頭後面長出來，逐字或逐詞出現。注意是接續不是抽換——整句被換掉會讓人覺得剛剛那句是假的
3. 完成：完整回覆＋來源標籤出現
4. 對比展開：點一下展開「一般 AI 會回：收到」的對照

【介面二 · 鍵盤建議條：防自爆】四個狀態
1. 待命：鍵盤正常使用中，建議條不存在（高度 0）
2. 觸發：使用者打的字帶風險，建議條從鍵盤上緣向上長出來（約 56dp），顯示一行提示，同時輸入框裡有問題的字詞被標記
3. 展開：點一下展開到約 160dp，顯示完整的建議句子與「採用」動作
4. 採用後：建議條收回，輸入框內容被替換

建議條的出現方式要**推開**內容而不是蓋住——它是鍵盤的一部分，不是浮在鍵盤上的東西。

動畫要克制：轉場時間 150–250ms，用 ease-out，不要彈跳、不要淡入淡出過長。這是工作工具，動畫的目的是讓人看懂發生了什麼，不是表演。
```

## 第 5 段 · 設計系統

方向定案、狀態做完之後才做這一段。

```
請根據我們定案的這個設計，建立一套設計系統，包含：
- 色彩調色盤（含每個顏色的用途與可及性對比值）
- 字體排版階層
- 基本元件（按鈕、標籤、卡片、輸入框、風險標記）的各種狀態
- 動效參數（時間、緩動曲線）

輸出成一個可下載的檔案，我要拿它去做另外四個畫面，以及專案簡報，讓風格保持一致。
```

導出後把檔案放進 repo 的 `design/` 資料夾，Brian 和做簡報的人都要用。
