## 組裝說明（示範一次，其餘題目只列動態的第 4 層）

- **/analyze**：第 1-3 層固定＝`引擎-analyze.md`（全文）＋`語氣-Zeno.md`（全文）＋`範例庫-回覆.md`（全文，6 則不抽樣）。第 4 層照 README 動態組（對象整筆＋粗篩 3-5 筆事實＋對話＋安全牌）。
- **/guard**：第 1-2 層固定＝`引擎-guard.md`（全文，含四則 few-shot）＋`語氣-Zeno.md`（全文）。第 4 層＝對象檔案＋對話最後 1-3 則＋草稿原文。

- 粗篩方法：用對話文字中的關鍵字，對 `facts.json` 的 `tags` 陣列做字面比對（README 沒指定演算法細節，本輪採最保守的字面命中，命中不足 3 筆就照實回報，不湊數）。

## 不過清單

> 本輪 13 題機械檢查（9 項）**全數通過**——因為執行者（本人）在模擬引擎輸出時，是照著規則謹慎、誠實地寫，屬於「模型認真執行時能力上限」的示範跑法。以下不是本輪的「不過」，而是**執行過程中發現的結構性風險**，依可能造成的後果嚴重度排序，供 Zeno／Brian 決定要不要補強引擎檔或 README：

1. **【高】Persona 的「三次彼此不同」不是設計保證，是巧合**
   檔案：`prompts/角色卡-諸葛亮.md` 第 29-32 行（「示範」段落）。
   這段示範用的原回覆，逐字等於本輪 P1-P3 測試的〈原回覆〉。也就是說，真正呼叫 LLM 時，模型極可能直接把示範措辭原樣或近乎原樣吐回來三次——prompt 裡沒有任何一句要求「多次呼叫要用不同開場句／不同用詞」。上台若要展示「每次改寫都不一樣」，這件事目前完全靠溫度抽樣運氣，不是引擎設計保證的行為。建議：若這個效果要上台演，在引擎極簡版三句裡加一句「用不同於範例的措辭改寫」，或乾脆不要在 demo 裡連續展示三次改寫。

2. **【中】G4 與 few-shot 例 1 的「對方訊息」逐字相同，但正確答案相反**
   檔案：`prompts/引擎-guard.md` 第 51-55 行（Few-shot 例 1）。
   例 1 教模型「看到『這個價格比別家貴很多耶』→ flagged:true」。G4 刻意用同一句客訴、換一份乾淨草稿，驗證模型是否只認對方那句就誤判。本次人工模擬判斷正確（flagged:false），但這只證明「認真讀規則會判對」，沒有反例可以佐證較弱的模型或高負載情境下不會被例 1 的表面相似度帶偏。建議在引擎檔加一個對照例：「同一句客訴，草稿乾淨 → 不出手」，把區分依據明釘在草稿而非對方訊息上。

3. **【中】/guard 測試靶子沒有 contactId，組裝規則要求的「對象檔案」層缺料**
   檔案：`prompts/README-組裝說明.md` 第 56-63 行（「/guard 的 system prompt 組裝」）。
   README 沒定義「沒有對象資料時第 4 層怎麼組」的 fallback，本輪只能寫「（未提供對象，略過此層）」代打。這既是本次測試靶子本身沒給 contactId 的問題，也暴露 README 沒把這個邊界情況寫清楚——建議補一條「無 contactId 時，第 4 層省略對象檔案，只放對話與草稿」的明文規則。

4. **【低】A2「這週還來得及嗎」缺乏「今天是星期幾」的上下文**
   檔案：`prompts/README-組裝說明.md` 第 16-36 行（第 4 層組法）；`prompts/語氣-Zeno.md` 第 12 行（「給時間就給具體的，不寫盡快」）。
   知識庫只有流程描述（週一出角度、週二給素材、週三上片），沒有「現在幾號星期幾」。要精準回答「這週來得及嗎」，理論上需要今天的日期，但第 4 層組裝規則沒有這個欄位——逼得回覆只能用條件句帶過（本輪示範用「您方便的話我們現在就開始排」迴避），跟語氣層要求的「具體時間」互相拉扯。建議組裝時第 4 層加一行「今日日期」。

5. **【低】A1／A3／A4 的〈相關事實〉粗篩命中偏少甚至掛零**
   檔案：`data/facts.json`（無「營收」「認證」相關 tag）。
   A1 只命中 1 筆（README 建議塞 3-5 筆）、A3／A4 掛零。這是知識庫覆蓋範圍問題，不是 prompt 缺陷——沒有相關事實時掛零、回「我確認後回覆您」是正確行為，本輪判定過。純粹記錄給之後擴充知識庫參考：如果產品希望常態命中 3-5 筆，粗篩演算法可能需要同義詞擴展（例如「營收」對應到一個尚未存在的財務類事實）。

6. **【極低／文件】`usage: internal` 引用限制只寫在 /guard 段落，卻宣稱「兩個引擎通用」**
   檔案：`prompts/README-組裝說明.md` 第 63 行。
   這條規則放在「/guard 的 system prompt 組裝」小節內，內文卻寫「兩個引擎通用規則」。實作者如果只讀 /analyze 段落，容易漏掉這條、忘記在 /analyze 組裝時也要在內部事實後面加註「（內部參考，不得寫入回覆）」。本輪 A5 有正確套用，但建議把這條規則搬到不分 /analyze／/guard 的共用段落，降低漏讀風險。
